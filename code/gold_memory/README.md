# Gold Memory:手工调优的"标准答案"记忆库

> 2026-07-10 立项。想法:给定一个样本,**手工把它的记忆库调到检索严格正确率 ≥95%**,得到一份"标准答案"记忆。它不是方法的产出,是方法的**标尺和老师**。

## 一、三个用途

| 用途 | 怎么用 | 回答什么问题 |
|---|---|---|
| **1. 上界测量(oracle)** | 冻结检索/答题代码,只换记忆库为 gold,跑评测 | build 环节还剩多少分可挖?(gold 分 − 自动 build 分 = build 差距;95 − gold 分 = 检索/答题的固有损耗) |
| **2. 范例引导** | 把 gold 的**结构与文体**(裁剪后的骨架,非全文)作为 few-shot 范例注入 distill/文章化 prompt | 模型照着好样子写,新样本的记忆自然趋向标准形态 |
| **3. 规则提取** | 手调过程中每一条"这样改为什么涨分"的经验,固化为代码校验或 prompt 规则 | 把人的组织直觉转译成自动 build 的机制 |

## 二、红线(防过拟合,必须遵守)

1. gold memory 用 **dev 样本(s0/1/2)** 的题反复调出来——它的分数**永远不算方法成绩**,任何表里出现必须标注 "oracle (hand-tuned)"。
2. 正式报数只认 **sample 3-9**(从未被任何调优碰过)+ 统一自动 pipeline。
3. 范例注入只传**结构和文体**(目录形态、文章写法、链接用法),范例内容是 s0 的事实,对其他样本的问题没有答案泄漏。
4. 调优时**只改记忆文件,不改代码不改检索 prompt**——变量唯一,量出来的才是"记忆质量"这一个因素的贡献。

## 三、构建协议(对 sample 0)

**起点**:文章化 pipeline 自动 build 的 s0 记忆库(v8article-b3 的 memory_sample0),复制到 `gold_memory/sample0/`。

**迭代环**(每轮):
1. 冻结代码,`--memory-dir gold_memory/sample0` 跑方案 B 评测(152 题,双口径)。
2. 逐条分析错题:信息缺失→补写(从原对话补,带 dia_id 锚);归档不合理→挪/并/拆;措辞不可检索→改写(保留专名);日期错→修。
3. 每轮记录改动清单和分数变化到 `gold_memory/tuning_log.md`——这本日志就是"规则提取"的原材料。
4. 停止条件:严格口径 ≥95%,或连续两轮无提升(那就是检索/答题的天花板,本身是重要发现)。

**执行方式**:agent 按上述环操作,人抽查关键轮次。

**产物**:
- `gold_memory/sample0/` —— 调优后的标准记忆库
- `gold_memory/tuning_log.md` —— 每轮改了什么、为什么、分数变化
- 提取出的规则清单(回填到本 README 第五节)

## 四、理想结构蓝图(先验设计,调优的起手式)

`ideal_example/` 里有一份手写的微型示例(s0 真实内容,2 个 topic + 1 个 timeline 月份),体现全部设计要素:

```
memory_root/
├── timeline/                    ← 代码的原子日志(确定性,永不手调坏)
│   └── 2023/05/25.md            一天一文件(YYYY/MM/DD,月日两位数字);每行: [日期] 事实 · [dia_id] → topics/路径
└── topics/                      ← 门内自由,文章文体
    └── Caroline/
        ├── adoption.md          ← 一篇带内联引用的小文章
        └── identity-and-support.md
```

文章要素(见示例文件):
- **标题**概括这条线索是什么事;开头一句**总述**(它的来龙去脉一句话)
- 叙事按时间推进,**绝对日期写进句子**并自动链接到 timeline
- **引用内联**:每个事实提及处紧跟 [dia_id],写到哪引到哪
- **专名/数字一字不丢**(书名、地名、数量原词保留)
- 粒度:同一件事的进展合在一段;不同线索分段/分标题;文件过大按子话题拆子文件

## 六、与主线的关系

- 不阻塞主线:消融链第四点(文章化)出分、10 样本正式跑,照常推进。
- gold memory 调优在这之后启动,用文章化后的库做起点(起点越好,手调越省)。
- 若 oracle 显示 build 差距已 <2 分,则范例引导/规则提取降优先级——钱花在刀刃上。
