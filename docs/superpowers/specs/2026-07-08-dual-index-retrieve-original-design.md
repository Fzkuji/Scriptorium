# NativeMem v8：双视图索引 + 回原文检索

日期: 2026-07-08
分支: feature/v7-agent-memory（v8 在其上迭代）
取代: v7 的"逐句提炼+verbatim 存储"写入路径（长对话上 85% 丢失、检索大面积翻空）

## 1. 一句话目标

记忆库不再逐字复制对话，而是把每件事存成**一行摘要 + 指回原文的位置(dia_id)**，同时按**话题**和**时间**两种方式各摆一份；答题时先用这两份缩小范围，再**回原始对话**读那几句精确作答。卖点：主动检索筛掉噪声，性能超过 Full-context 的 72%、冲 80%。

## 2. 为什么这么做（定位）

- **对标 with-original 口径**（允许回原文），对手是看原文的方法：Full-context 72.7 / Mem0 61.8 / LightMem·Nemori ~73 / MemOS 72.6。
- **卖点是性能不是成本**：Full-context 把整段对话一股脑塞给模型，被无关信息淹没，卡在 72%（temporal 类只有 53）。我们让模型**主动搜索+筛选**，只把相关的几句原文喂给答题，信噪比高 → 冲 80%。成本/效率上更贵，认了。
- **双视图直击基线最弱项**：LoCoMo 的 temporal（时间类）问题是所有方法软肋（Full-ctx 53 / Mem0 54）。一条专门的时间线索引把它吃下来，是反超的关键突破口。

## 3. 记忆库长什么样

底层每件事**只存一次**语义内容，用两种"视图"当两种摆放方式，都指向同一批事件、都不存原文。**两个视图都用文件夹**（单文件长了没法管、模型还得在大文件里翻），但分法不同：

```
memory_sample0/
  timeline/                    ← 时间视图：按 年/月 分层，好管好定位
    2023/
      05-May.md
      06-Jun.md
      07-Jul.md
    2024/
      01-Jan.md
  topics/                      ← 话题视图：按话题并列
    Caroline-adoption.md
    Caroline-support-group.md
    Melanie-painting.md
```

**时间视图为什么按 年/月 分文件夹**：单个 timeline 文件时间长了会大到没法管、模型得在里面慢慢翻；分成 `年/月-英文.md` 后，模型知道大概时段就直接顺路径打开对应文件，一步定位。月份用 `05-May` 而非纯 `05`——数字保排序、英文让模型一眼知道是五月，不会把 `05` 误解成日期或别的。一个月的事件也就几条到十几条，文件内按日排即可，不用再拆到每天一个文件（大部分天是空的、太碎）。

**话题视图**天然是多个并列话题（收养、支持小组、绘画……），一个话题一个文件，查哪个开哪个。

**每件事固定写成一行**（两个视图里格式一致，日期写完整不让模型猜）：
```
[2023-05-07] Caroline 去了 LGBTQ 支持小组 · [D1:3]
[2023-05-20] Caroline 开始研究收养机构 · [D2:5]
[2023-07-11] Caroline 提交了收养申请 · [D9:2]
```
- `[YYYY-MM-DD]` 完整日期（temporal 排序用；文件内按日排）
- 一句话摘要（是什么事，够搜索定位即可，不逐字）
- `[dia_id]` 指回原始对话的位置（回原文取细节的钩子）

同一事件在 `timeline/2023/05-May.md` 和 `topics/收养.md` 里各一行，因为都极短，冗余可忽略。跨月的先后问题（"先做 A 还是 B"）：模型打开相关的那两三个月文件对比即可。

## 4. 存记忆怎么写（build，按 session 一块）

一个 session（~600 token）一块，一次调用提炼出这个 session 的**事件行清单**（不逐句、不 verbatim），然后落盘：

1. **提炼（1 次大模型调用）**：`distill_events(session_text, date, dia_ids)` → 返回若干事件行 `{when, summary, dia_id, topic}`。让模型只挑"值得记的事件"，写一句话摘要 + 归一个话题名 + 标 dia_id。**不复制原文。**
2. **落盘（代码做，不靠模型手写）**：每个事件行按它的日期和话题，代码写进两处
   - `timeline/{YYYY}/{MM}-{Mon}.md`（按完整日期算出年/月路径，文件夹/文件不存在就建，文件内按日插入排序）
   - `topics/{topic}.md`（话题文件不存在就建）
   
   落盘由代码保证写全，杜绝 v7"模型手写到一半被截断→丢记忆"的问题。

**关键改动 vs v7**：v7 让模型用 bash 一条条手动存（5-6 次调用/块、易丢）；v8 改成**模型提炼一次 + 代码落盘**（1-2 次调用/块、不丢）。这是向"提炼+代码落盘"靠拢，用可靠性换掉 v7 的"完全自主 bash 存储"。

## 5. 答题怎么用（检索 + 回原文）

分三步，模型主动筛选是核心：

1. **定位**：看问题属于"什么"还是"什么时候"——
   - 问"什么/谁/哪里" → grep `topics/` 找相关话题文件
   - 问"什么时候/先后/多久" → 读 `timeline.md` 按时间推
   （模型自己判断走哪份，或两份都看）
2. **回原文**：从命中的事件行拿 `dia_id`，**回原始对话**读那几句原文（这一步是 with-original 的关键，允许看 raw）。
3. **作答**：只拿这几句相关原文作答，不把整段对话给模型。

**筛选要狠**：宁可精准给 3 条原文，不要模糊给 30 条——否则退化成小号 Full-context，优势没了。

## 6. 回原文的实现

- build 时保留一份**按 dia_id 可查的原始对话**（`NATIVEMEM_NO_ORIGINAL` 相关屏蔽在此方向关掉，hide_raw 关掉）。
- 提供一个工具/函数 `read_turns(dia_ids)`：给定若干 dia_id，返回对应原始对话原文（含前后各 1 句上下文）。检索 agent 拿到事件行的 dia_id 后调它取原文。
- dia_id → 原文的映射从 `locomo10.json` 直接建（turn 有 `dia_id`/`speaker`/`text` 三字段）。

## 7. 边界与降级

- **一个 session 没有值得记的事件**：提炼返回空，跳过，不写。
- **话题名爆炸**（模型每次起新名 → 话题文件太碎）：提炼时把已有话题名列表喂给模型，让它优先复用；仍碎则靠后续 consolidate 合并（复用现成的 `consolidate_topics`）。
- **回原文取到的 dia_id 不存在/越界**：`read_turns` 跳过无效 id，返回能取到的部分，不崩。
- **temporal 排序**：事件按完整日期路由到 `timeline/年/月-英文.md`，文件内按 `[YYYY-MM-DD]` 插入排序（代码保证有序），模型顺路径打开对应月份读到的就是有序时间线。

## 8. 复用与新增

- 复用：`split_into_chunks`（size=50 按 session 切）、`normalize_date`、`consolidate_topics`（话题合并）、`execute_tool` 的 grep/cat（检索）。
- 新增：`distill_events`（提炼事件行）、`write_events`（代码落盘 timeline + topics）、`read_turns`（回原文）、`_collect_v8`（三步检索）。
- 弃用（保留不删）：v7 的 `process_chunk_agent` / `_run_store_agent`（模型手动 bash 存储）、`_AGENT_STORE_PROMPT`。v8 走独立分支 `NATIVEMEM_PROMPT=v8`。

## 9. 实验与验收

- **主指标**：LoCoMo 全 10 样本、LLM judge（gpt-4o-mini + 32B 双 judge）overall 分。目标 >72.7（超 Full-context），冲 80。
- **分类看**：重点看 temporal 类是否显著高于基线的 53（验证时间线索引的价值）。
- **消融**：只话题视图 vs 只时间视图 vs 双视图（证明双视图必要）。
- **成本记录**：build/检索的调用数与 token，如实报告"更贵但更准"。
- **先小后大**：先 sample0 跑通、人工核对记忆库是双视图结构 + 回原文能取到 + 不丢事件，再上全量。
