updated 2026-06-25 — 覆盖 2024–2026.06 所有主要 LLM Memory 研究（30+ 方法）

§1 研究背景

LLM Wiki

Karpathy LLM Wiki (2026)
LLM 增量读取原始文档，维护结构化 markdown wiki。三层架构：raw sources → wiki → schema。文档组织由 prompt schema 决定，不基于模型概率。对标：我们的方法可以用在 wiki 的组织层——Karpathy 解决"内容整理"，我们解决"按什么结构整理"。
MemCoT (arXiv 2604.08216, 2026)
给 LLM 配备外部记忆模块，推理时通过 CoT 调用记忆条目。记忆组织是预定义结构。

概率与检索

Perplexity Trap (ICLR 2025, arXiv 2503.08684)
发现 PLM 检索器系统性高估低困惑度文档的相关性，提出 CDC 去偏。关键关联：证实"模型概率影响检索排序"这个现象。我们反过来利用它——把概率偏差从 bug 变成 feature。
eRAG (SIGIR 2024, arXiv 2404.13781)
用 LLM 对单文档生成回答的质量来评估文档检索价值。不重组文档结构。
Semantic Perplexity (arXiv 2510.21440, 2025)
量化"有/无检索内容时 LLM 回答困惑度差异"作为检索质量度量。用困惑度衡量效果，但不涉及文档重组。
LLM Hidden-State Confidence for RAG (SIGIR 2025, arXiv 2509.06472)
用 LLM hidden states 构造 confidence 模型，量化检索文档对回答的增益，据此重排。最接近方向：它用模型内部状态评估文档，但方向是 rerank 已有文档，不是重新组织文档结构。

知识外化与自适应检索

Self-RAG (ICLR 2024, arXiv 2310.11511)
训练 LLM 插入 reflection tokens 自适应决定是否检索。仍依赖外部检索器。
SimRAG (NAACL 2025)
两阶段微调改善 RAG 检索质量。文档组织仍是给定的。
MACR (arXiv 2606.20245, 2026)
用语义熵量化 LLM 置信度，将模型内部知识外化为文本并与外部知识对比。目的是冲突检测，不是文档编排。
Knowledge Mechanisms in LLMs: A Survey (arXiv 2407.15017, 2024)
综述 LLM 中知识的存储、提取、编辑机制。理解模型知识表征的背景文献。

文件与知识组织理论

我们的方法用文件系统（markdown 文件 + 目录）作为记忆载体，结构设计需要理论基础。以下调研覆盖个人信息管理、信息架构、知识管理、LLM 文件系统和认知科学五个方向。

方向关键研究核心结论对我们的启示
个人信息管理（PIM） Boardman & Sasse 2004 "Stuff Goes into the Computer and Doesn't Come Out"：研究人怎么组织文件，发现堆叠 vs 归档策略因人而异，同一人在不同工具间的层级结构也不同。
William Jones 2007/2010 PIM 综述：总结三大挑战——finding（找到）、keeping（决定存哪）、re-finding（再次找到）。 		没有"最优文件数量"或"最优层级深度"的通用答案，最优取决于使用者（对我们来说就是 LLM）。信息碎片化（相关信息散落不同位置）是核心问题。 我们的 wiki 天然避免碎片化（单一文件系统 + markdown 链接）。RSP 让"使用者"（LLM）自己决定结构，符合 PIM "最优取决于使用者"的结论。
信息架构：层级结构 Dwight Miller 1981 广度 vs 深度实验：测试 1层64项 / 2层8项 / 3层4项 / 6层2项 的检索效率。
Miller's Law (7±2)：人的工作记忆容量约 7±2 个项目。 		极扁（1层64项）和极深（6层2项）都不好，中间配置（2层、每层8项）最优。更重要的发现：标签清晰度比层级结构更重要——文件名足够清晰时，即使层级较深也能高效导航。 对 LLM 来说"认知限制"不是 7±2 而是 context window，但原理类似——ls 列出太多文件时选择困难。我们的"具体名词命名"约束直接对应"标签清晰度"这个核心因素。
知识管理方法 Zettelkasten（Niklas Luhmann）：每条笔记是独立卡片，靠链接组织。A-Mem 用的就是这个。
PARA 方法（Tiago Forte）：Projects/Areas/Resources/Archives 四类强制分类。
文件夹 vs 标签 vs 链接对比 		Zettelkasten 灵活但规模大了检索变难。PARA 分类清晰但僵化。混合方案最好——文件夹做粗分类 + 链接做跨类关联。 我们的 wiki 是天然的混合方案（文件/文件夹层级 + markdown 链接关联）。但 Zettelkasten 的"规模大了检索难"问题对我们也存在——RFR 的目标之一就是应对这个。
LLM 语义文件系统 LSFS (ICLR 2025)：用 LLM 替代传统文件系统命令，通过自然语言做文件 CRUD + 语义检索。构建语义索引，支持 semantic group-by、join 等操作。
代码：GitHub 		检索准确率比传统文件系统高 15%，速度快 2.1×。证明了 LLM 管理文件系统是可行的。 "LLM + 文件系统"方向的先驱验证。但 LSFS 是通用文件管理工具，不是记忆系统——没有 RSP（不考虑检索者视角放置）、不涉及存储内容的保真度（copy vs 摘要）。
认知科学：记忆组织 Collins & Quillian 1969 语义网络模型：人的语义记忆按层级组织（动物→鸟→金丝雀），节点之间用属性链接。
Tulving 1972 情节记忆 vs 语义记忆：情节记忆按时间+上下文组织（何时何地发生了什么），语义记忆按类别组织。 		两种记忆检索方式不同——语义记忆靠类别导航，情节记忆靠时间/场景线索。 我们的 wiki 天然对应这两种记忆：文件按实体（人名/项目名）组织 = 语义记忆，文件内按时间戳 [YYYY-MM-DD] 排列 = 情节记忆。5W1H 框架（Tulving 1972）确保情节记忆的完整性。

现有方法中没有任何一个同时覆盖四类问题。名字优化几乎无人关注（仅 HORMA 间接涉及）。粒度优化只做合并（细→粗），无拆分（粗→细）。关联都在存储时建立，无事后补充。我们是唯一基于检索反馈驱动的结构优化方案。
