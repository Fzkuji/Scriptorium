# v4 — 双层记忆(提炼句 + 原文垫底)及变体

> 变体:v4 / v4o2 / v4o2b / v4o2b-k8 / v4full / v4-dual。开关 `NATIVEMEM_PROMPT=v4`。

## 设计

针对 v3 的"照抄原文"根问题,把写入改成**双层**:
- **提炼层**:精炼事实句,负责被检索命中。
- **原文层**:verbatim 垫底,负责核对。

借鉴 Mem0(禁概括 + 专名优先)、Memobase(时间精度自适应)、LightMem(source_id 回指)。这是优化线 **O1**。

## 实验与结果

### v4(O1 双层)

- **5.4-mini J 75.0**(+4.6 vs baseline 70.4)。大胜:temporal 70.3→**91.9**(+21.6,时间归一化生效)、multi-hop 50.0→59.4。
- **回归**:single-hop 80.0→74.3(-5.7)——5.4-mini 过度概括提炼句、丢专名('Becoming Nicole'→'the book',甚至 dog→horse);细节其实在 verbatim 层,但检索/答题没回退去读。
- **跨模型崩溃**:千问 J = **24.3**,62% 空检索——千问建了 27 文件 3 层深目录,旧检索"ls + 按文件名挑"迷路。

### v4o2(O2 激进跨文件 grep)

- 把 COLLECT 改成递归 grep 所有文件 + top-20。召回升(4.0→7.9 mem/题)但 **J 掉到 70.4**(temporal 92→78,multi-hop 59→53)。
- **同"拆文件"陷阱:检索更多 ≠ 答得更好,噪声淹没干净答案**。→ 弃激进 grep。

### v4o2b(精准 grep)

- 改成 `grep -rin keyword` 精准递归内容搜索(替代按文件名挑),定位条目无论嵌多深。
- **救千问:J 24.3→48.7**,空检索 94→9 题,各类均衡。5.4-mini 换 2 分稳健(75.0→73.7)。
- 诊断:剩余 gap 是千问 answerer 天花板(30B),非检索 bug。

### v4o2b + TOP_K=8

- 千问 Full-ctx=80.9(不弱)。k=20 时 60/199 题命中 20 条上限、千问答 "Unknown"。切 k=8:**千问 J 48.7→54.6**(+5.9,single 51→63)。
- 剩余短板 temporal=35:千问提炼时把日期算错("7 May 2023"→"2023-05-06")。→ 催生 v5(提炼/存储解耦,把日期心算从提炼移除)。

### v4full(v4 提炼 prompt 全量跑)

- 5.4-mini,cat1-4,10 样本部分(实收 1109 题):**overall 82.1**(single 84.6 / multi-hop 83.5 / temporal 75.8 / open-domain 76.8)。
- **口径验证(关键)**:with-original 82.7 → **no-original 82.1**,仅 **-0.6**;千问 v6 68.8→68.6(-0.2)。**近零下降证明分数来自高质量提炼、不是偷看原文**。82.1 甚至超 Full-context 上界(~80)——"结构化记忆 > 直接倒原文"。

## 发现

1. 确立**自适应加工强度**主线——最优加工强度取决于 backbone 能力(文献空白 = 潜在贡献点)。两档:强档 = v4(5.4-mini 75.0,超 LightMem 73)、弱档待 v6(千问)。
2. **raw 泄漏修正(hide_raw)**:发现之前的 "no-original" 其实泄漏了——检索 grep 的 cwd=memory_dir 含 raw/ 子目录,`grep -rin term .` 扫进了 raw/。修法 `execute_tool(hide_raw=True)`。**这是"干净口径"意识的转折点**,先前全量数字须重跑。
3. v4 暴露三条,分别催生后续:5.4-mini 过度概括丢专名 → 待解;千问一次 bash 干 7 件事认知过载、日期算错 → **v5 提炼/存储解耦**;raw 泄漏 → hide_raw 干净口径。
