# v3 — 弃自定义工具 → 标准 bash(核心 baseline)

> 逐字固化见 [`../nativemem_v3_baseline.md`](../nativemem_v3_baseline.md)(固化日期 2026-07-04)。本文件是摘要 + 实验/发现。

## 设计

核心改动:**把 6 个自定义 Python 工具替换为单一 `bash` 工具**,模型直接写 `ls -lhR` / `grep '^#'` / `cat` / `sed` / `mkdir` / `mv` 标准 shell。

**5 阶段流程**:
1. **构建** `process_chunk`:SYSTEM_PROMPT 走 RAM 三步 THINK→BROWSE→STORE;**照抄原文、禁止总结**;每条带 `[YYYY-MM-DD]` + `[source]` 回链;矛盾信息追加不覆盖。
2. **重组** `check_and_reorganize`:文件 >100 行拆分、目录 >15 文件分子目录。
3. **验证**。
4. **修复**:STRUCTURAL / SLOW / MISSING 三类,只加链接不改内容。
5. **检索**:评测适配改 **collect 模式**(只收集条目、不作答,最多 20 条),交统一 answerer。

`v3opt` = 加 pre-inject 目录列表优化(省 14% 构建调用),但被证伪回退。

## 实验与结果

- **LongMemEval**:LJ 从 45.0 → **55.3**(bash 工具 + 拆分规则)。
- **F1(s0,deepseek-v4-flash,199 题)**:Overall **0.376**;对比 A-Mem 0.406、Mem0 0.176。**Adversarial 0.723 远超**(prompt 里有 "No information available")。
- **构建指标**:1231s / 480 调用 / 3.3M token / 25 文件 / 重复标题 **0** / 找到率 **86%** / 验证通过 **100%**。
- **同协议首跑(s0,5.4-mini 建+答,4o-mini judge)cat1-4 J = 70.4** —— 固化为 baseline。
- v3opt(pre-inject):LJ=55.3 无改善 → 回退。

## 发现

**s0 归因(152 题错 45)**:
1. 检索命中率低(17 道)——关键信息淹没在长原话里。
2. 时间没换算(9 道)——无提炼层,写入时日期未归一化。
3. 细节被概括掉(7 道)。

**深层根源:明令"照抄原文禁止总结"太像 RAG,缺少主动加工。**

**另一致命问题:换模型脆弱** —— deepseek 听话拆成 25 文件;5.4-mini 不拆,堆成 2 个 450 行大文件,构建 token O(n²) 滚雪球。**收尾拆文件被实测证伪是负优化**(J 70.4→53.9:5.4-mini 拆得烂、打散条目丢日期锚点)。

→ 定 baseline = 不拆版 70.4;规划 O1/O2/O3 三条优化线 → **v4**。
