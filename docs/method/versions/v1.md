# v1 — 自定义工具 + 照抄原文

> 最早期实现(`memory_builder.py`)。整理自 git 提交、`docs/archive/EXPERIMENT_RESULTS.md`、`our_results.md §0`、`results/nativemem-v1-locomo-full10/`。

## 设计

- **模型**:构建 / 检索 / judge 全用 qwen3.6-flash。
- **方法**:RSP(Retrieval-Structured Prompting) + Copy-Don't-Generate(照抄原文,不总结) + 5W1H 框架。
- **工具**:6 个自定义 Python 工具(ls / cat / grep_headings / find 等),函数调用式检索。
- **流程**:对话切 10-turn chunk 逐块写入;检索直接作答(未解耦 answerer)。

## 实验与结果

**自 judge(qwen3.6-flash,0-100 连续分,口径不可比)**:
- 50 题/样本组:Overall LJ 83.5(single 85.6 / temporal 88.1 / multi-hop 61.2 / open-domain 88.9)。
- 全 1986 题:Overall LJ 66.3(adversarial 仅 26.6,严重拖累)。

**Mnemis 统一 judge(gpt-5.5)重评 1986 题(唯一可比口径)**:
- Overall **75.0**(single 78.3 / temporal 86.2 / multi-hop 67.7 / open-domain 89.5 / adversarial 39.1)。

**消融(s0,gpt-5.5 judge)**:
- Wiki full **88.1** > Full-context 80.7。
- w/o Copy 83.5(-4.6)、w/o RSP 79.1(-9.0)、**Flat memory 31.7(灾难 -56.4)**。
- 证明:结构化和照抄各有贡献,扁平存储不可行。

**缩放实验**:换检索模型(qwen→deepseek)分数几乎不动 → **瓶颈是存储质量,不是检索能力**。

## 发现

1. multi-hop 最弱——模型只读一个文件,不跨文件推理。
2. MISS 检索比 FOUND 贵 2.9× token;67% 题 4 轮内解决。
3. 硬伤:self-judge 口径不可比、adversarial 极差。

→ 催生 **v2**:换更强模型(deepseek)+ 引入基线对齐意识。
