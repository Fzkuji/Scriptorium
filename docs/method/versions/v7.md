# v7 — Agent 自组织 + 三节奏结构维护

> 分支 `feature/v7-agent-memory`,设计蓝图 [`2026-07-06-agent-self-organized-memory-design.md`](../../internal/superpowers/specs/2026-07-06-agent-self-organized-memory-design.md)。**理念最完整的一版,但实现路线在弱模型/长对话上崩溃。**

## 设计

彻底放弃硬编码路径,**代码只给顶层视图 + bash 工具,结构全由模型自组织**。核心是**三节奏(three-rhythm)结构维护**:

| 节奏 | 时机 | 做什么 |
|---|---|---|
| **节奏1 即时维护** | 每 chunk | `process_chunk_agent`:分层提炼 + agent 用 bash drill-in 自己决定放哪(三规则:放最相关文件 / 见重复就地合并 / 命名沿用惯例) |
| **节奏2 轻量再平衡** | 每 session 末 | `tidy_local`:`inspect_structure` 体检标 ⚠(过大/过小/目录过宽/近义重名),模型只修被标记项 |
| **节奏3 全局重构** | 增长触发 | `reorganize_library`:模型拿全局视野整套重排,完后重置 snapshot 基线 |

分工红线:**代码只测量报告失衡(确定性),模型决定怎么修(语义)**;代码不写死任何记忆内部路径。

配套:检索走 top-view drill-in + `hide_raw=True` 堵原文泄漏;加终止压力防 store-agent 重复写同一事实。

## 实验

### SUMMARY_PAGE 消融(唯一留下结论的实验)

见 [`../../experiments/results/ablation_summary_page.md`](../../experiments/results/ablation_summary_page.md)。拆子目录后**要不要留同名摘要页**(qwen3.6-flash,s0 前 2 session,`BIG_FILE=4` 强制拆分)。

**结论 default=off 更好**:弱模型无法实现"每子主题一行摘要 + 链接"的语义,把摘要页当普通内容文件填,自创 `index.md` 制造散文件 + 目录混杂的乱结构,检索时 q2 只捞到 1 条。off 是干净两级树、检索更稳。`on` 保留作强模型可选项。

### 评测

`v7full-qwen36flash-locomo` 只有 build 产物,`v7fast-test-s0` 是 build + 检索 dump,**均无 end-to-end judge 分**——v7 没有干净的评测数字留存。

## 发现(致命伤,记在 v8 spec 开头)

**v7 的逐句提炼 + verbatim 存储写入路径,在长对话上 85% 丢失、检索大面积翻空。** 让模型用 bash 一条条手动存(5–6 次调用/块),弱模型手写到一半被截断就丢记忆。

→ 直接触发 **v8**:用"提炼一次 + 代码落盘"换掉 v7 的完全自主 bash 存储。

## 备注(与当前工作的关联)

v7 的**理念**(模型自组织 + 三节奏整理 + 两级视图)是正确方向,但**实现**崩了。v8 为求稳退回了代码硬编码双目录,**把 v7 的三节奏整理搁置了**——这正是 v8 当前 topic 文件失控、检索导航短板的根源。补齐 v8 到这套设计,是 2026-07-09 定的下一步方向(见 [`../README.md`](../README.md) §4)。
