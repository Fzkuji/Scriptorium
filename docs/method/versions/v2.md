# v2 — 加轨迹传递 + 多轮修复

> `memory_builder_v2.py`。整理自 `our_results.md §4`、`results/nativemem-v2-locomo-s0/`。

## 设计

- **模型**:构建 / 检索换 deepseek-v4-flash(阿里云 API)。
- **工具**:仍用 **6 个自定义 Python 工具**(未换 bash)。
- **相比 v1 加了**:轨迹传递(把上一轮 bash 轨迹喂回)+ 多轮修复机制。
- **目标**:解决 v1 的写入不全 / 检索找不到。

## 实验与结果

无正式 LLM-Judge 分,以过程指标记录:

| 阶段 | 找到率 | 验证通过率 | 重复标题 | 文件数 |
|---|---|---|---|---|
| 修复前 | 59% | 65% | 10 | 50 |
| 修复后(轨迹传递+多轮修复) | **67%** | **90%** | 10 | 50 |

## 发现

1. 自定义工具让模型认知负担重。
2. 重复标题(10 个)控制不住。
3. 文件数虚高(50)。
4. 找到率仍只卡在 67%。

→ 直接催生 **v3**:弃自定义 Python 工具,改用标准 bash。
