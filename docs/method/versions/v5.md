# v5 — 提炼/存储解耦 + 强制事件抽取

> `results/v5-qwen-s0/`、`v5-54mini-s0/`。answerer=qwen3-30b、judge=gpt-4o-mini、s0/152 题。

## 设计

- **动机**:修弱模型"边提炼边存 → 结构崩塌"。
- **改动**:把提炼与存储**解耦**;强制"事件抽取"(此前把 events 压成 states,丢了时间信息)。
- **存储仍走硬编码** `people/{person}.md`(一人一大文件,主题全挤一起)。

## 实验与结果

`v5-qwen-s0`(answerer=qwen-30b):
- overall(cat1-4)J = **66.4**(对比 v5 修复前 54.6,事件抽取修复带来 +11.8)。
- single 64.3 / multi-hop 59.4 / temporal 75.7 / open-domain 69.2 / adversarial 10.6。
- build:738.8s / 278 calls;retrieval **858 calls / 8.5M tok_in**(很贵——退回 grep 硬搜)。

## 发现(直接写进了方法蓝图 §1)

v5 病根,`memory_management_design.md §1` 明确记录:
- 一个实体 **60+ 主题标题**,大量近义未合并(`mental health career/work/counseling` 拆三个)。
- 同名 `## art` 在一个文件里出现三次。
- 根因:**逐段处理、每段只看当前内容、看不到已有结构**——处理第 30 段时不知道 `## art` 已存在,又建一个。

结构一乱 → 检索退化成关键词 grep(措辞对不上就翻空)。

**结论:根子在构建不在检索,需要一个独立的"周期性自我整理"环节。**

→ 催生 **v6**(分层提炼 + 代码托管存储,止住结构崩塌),并孕育了 v7 的"三节奏整理"设计。
