02

方案 A（两模型）vs 方案 B（单模型）

3 个样本(0/1/2)合并。方案 A:检索 agent 喂事件行+原文 → 独立 answerer 重新答题(标准公平对比协议)。方案 B:单个模型在连贯上下文里检索并直接答题(NATIVEMEM_V8_SINGLE=1)。

类别方案 A方案 BΔ (B−A)
Overall83.989.9+6.0
Temporal75.684.4+8.8
Open-domain76.290.5+14.3
为什么单模型更好 — 两模型交接会丢信息:检索模型已经在上下文里把答案推理出来了,却必须把记忆传给一个从零重新推理的新 answerer。单模型省掉这次交接,质量反而更高。

04

chunk size 扫描

固定方案 B + sample0，扫 NATIVEMEM_CHUNK_TURNS ∈ {6,10,15,20}（每 chunk = 一次 distill_events 调用）。目的:找覆盖率不掉的前提下最省的 build。n=152。

读法 — build 成本随 chunk 增大单调下降(6→20:时间 −43%、输出 token −42%,无噪声)。评分则非单调:6/10/20 都在 88–93,只有 15 掉到 84.9。multi-hop 只有 32 题,15 分摆动 ≈ 5 题,是单样本噪声,不是真实的覆盖率悬崖。要定 chunk 需多样本确认,不能信单样本"最优"。
