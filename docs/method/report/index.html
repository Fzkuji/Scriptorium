02

演进主线

一句话:工具在简化、加工在加深、结构组织权在"代码 ↔ 模型"之间摆动直到找到甜点、口径在收紧。

v1
自定义工具 + 照抄原文 · 75.0(gpt-5.5 重评)
qwen 自 judge 虚高;multi-hop 最弱、adversarial 极差。
v2
加轨迹传递 / 多轮修复 · 找到率 67%
自定义工具仍笨,重复标题控不住。
v3
弃自定义工具 → 标准 bash · 70.4 baseline
"照抄禁总结"太像 RAG;换模型崩(5.4-mini 堆大文件)。
v4
双层:提炼句 + 原文垫底 · 强档 75.0 / 全量 82.1
首超 Full-context;逼出精准 grep + TOP_K + hide_raw 干净口径。
v5
提炼/存储解耦 + 事件抽取 · 66.4
暴露"无自我整理 → 结构腐化(60+ 近义主题)→ 检索退化"。
v6
分层提炼 + 代码硬编码路径 · 弱档 68.4
弱模型止损,但代码接管"放哪"伤强模型、扼杀自组织。
v7
agent 自组织 + 三节奏维护 · 无干净评测分
理念最完整,但逐句 verbatim 存储长对话 85% 丢失。
v8
提炼一行 + dia_id、双视图、回原文 · 88.8
甜点:代码落盘保证写全 + 回原文兜底。单模型 > 两模型。
贯穿的张力 — 结构的组织权归谁?摆了四版:v5 放任→腐化,v6 硬编码→枷锁,v7 给对理念但实现崩,v8 拿高分却为求稳退回代码硬编码双目录,把 v7 的整理环节搁置了。今天的 138 文件失控 = v5 病根在 v8 里重现——环节 B(周期性整理)从设计到现在一次都没真正实现过。

方案 A / B · 3 样本合并

A=检索喂事件行+原文给独立 answerer(两模型)。B=单模型检索+直接答(NATIVEMEM_V8_SINGLE=1)。n=385。

类别方案 A方案 BΔ
Overall83.989.9+6.0
Temporal75.684.4+8.8
Open-domain76.290.5+14.3
每题 token17,89113,417−25%
B 定为主方案 — 全面胜 A 且更省。两模型交接有损耗:检索模型已推出答案,却要传给从零重推的新 answerer。单模型上下文连贯,更准更省。

06

已诊断短板

基于 v8ab3-B 的 15 道 open-domain 错题归因。

导航/召回 · 12
写入 · 2
答题 · 1

12/15 是导航问题:信息在双视图里都存了,模型在扁平的 topic 清单里选错文件或没走到。根因两条:

1 · 检索地图残缺 — _v8_topic_list 只列 topics/、不含 timeline/,双视图在检索起点瘸一条腿。
2 · 结构无整理 — topic 由 LLM 自由起名、代码机械追加,单样本文件数 12/72/138 失控(v5 病根重现)。v8 从未实现环节 B。

下一步:把 v8 补齐到设计蓝图——检索地图给顶层目录树(含 timeline)、写入模型自组织放置、补上环节 B 周期性整理。整理频率 / chunk / 加工强度是待实验旋钮。
