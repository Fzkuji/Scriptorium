NativeMem v8 · 短板图解

模型进门,只拿到半张地图

open-domain 15 道错题里,12 道不是记忆没存,而是模型导航到错地方。下面用三步说清楚它错在哪、怎么修。

1 · 记忆有两个视图,信息其实都存了

每条对话蒸馏出的事件,同时写进时间线(按年-月排)和主题(按人-事聚合)。以"Maria 去 hiking"为例,两边都有它。

📅 timeline/2023/07-Jul.md
D24:6 · Maria 教会野餐 存了
D25:2 · Maria 和教友去 hiking 存了
D27:1 · Maria 报名 aerial yoga 存了
🗂 topics/Maria-outdoor.md
D25:2 · hiking with church friends 存了
D24:6 · church picnic 存了

写入没问题——金标信息在两个视图里都能 grep 到。瓶颈在下一步。

2 · 但模型进门拿到的"地图"只列了主题,没列时间线

检索起点,代码把一张目录清单(_v8_topic_list)喂给模型当地图。问题:这张清单只列 topics/ 文件名,完全不列 timeline/。

✕ 现在的地图

模型第一眼只看得到主题文件

topics/
  Maria-outdoor.md
  Maria-work.md
  John-family.md
  ...

timeline/  ← 看不见
  2023/07-Jul.md
  2023/08-Aug.md

✓ 补上之后

主题 + 时间线骨架都在起点可见

topics/
  Maria-outdoor.md
  Maria-work.md
  ...

timeline/
  2023/07-Jul.md  (14 事件)
  2023/08-Aug.md  (9 事件)

后果 — 问"Maria 七月做了什么户外活动",模型看不到 timeline 的月份索引,只能在主题文件里盲翻,很容易抓到同月相邻的错事件。

为什么时间线没看到?——不是丢了,是当初就没喂

追到代码里,原因就在这个 7 行的地图函数 _v8_topic_list(run_nativemem.py:286)。它只 listdir 了 topics/ 目录,从头到尾没碰 timeline/。

# 列出 topics/ 下所有话题文件名，当检索的"地图"喂给模型。
def _v8_topic_list(memory_dir):
    topics_dir = os.path.join(memory_dir, "topics")   ← 写死只看 topics
    names = sorted(fn[:-3] for fn in os.listdir(topics_dir)
                   if fn.endswith(".md"))
    return "\n".join(f"- {n}" for n in names)
    # timeline/ 目录:这里一次都没出现

不是 bug,是入口和存储脱节:

✓ 存储层(distill 时)

两个视图都写。timeline/ 和 topics/ 里信息都齐。

✕ 检索入口层(这个函数)

只把 topics/ 拼进地图。timeline/ 存在,但模型进门看不到。

推测的成因 — v8 先做的主题视图,地图函数跟着主题写死。时间线视图是后加的,加的时候在存储层两边都补了,但这个检索入口的地图函数忘了同步更新。于是"库里两个视图都在,模型进门只看得到一个"。

修法 — 在这个函数里再 listdir 一下 timeline/,把年-月文件拼进返回字符串(顺手带上每月事件计数)。改动就这一个函数。

3 · 于是它这样走错门(真实错例 s2_q128)

金标答案是 hiking(D25:2),两个视图都存着。看模型的实际走位:

Q
问:Maria 上个月和教友一起做了什么户外活动?金标:hiking(D25:2)
1
地图里只有 topics/,看不到 timeline 的七月索引时序线索(“上个月”)用不上
2
在 Maria-outdoor.md 里 grep,命中一堆相邻事件picnic 和 hiking 挨在一起,语义又都是“教友+户外”
3
选了 D24:6 picnic 回溯原文,答成 “church picnic”✕ 错召回:选中了语义相近的邻居

关键 — 信息一直在库里。模型不是没存,是在扁平的主题清单里挑错了那一条。给它时间线骨架,它第一步就能靠“上个月”直接定位到七月,不用盲挑。
